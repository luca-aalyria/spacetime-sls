# LEO Constellation Builder and Coverage Simulator

## 1. Internal representation

The simulator shall use an explicit list of satellites as its canonical internal representation.

Each satellite shall contain:

* satellite identifier;
* epoch;
* semi-major axis (a);
* eccentricity (e);
* inclination (i);
* RAAN (\Omega);
* argument of perigee (\omega);
* mean anomaly (M_0), or equivalent orbital phase;
* optional shell, plane and slot identifiers;
* optional payload, beam and link-budget parameters.

Constellation families such as Walker Delta, asymmetric multi-plane, repeating-ground-track and Flower/lattice constellations shall be implemented as generators that produce this explicit satellite list.

The propagation and coverage-analysis code shall not depend on which generator produced the constellation.

## 2. Required constellation generators

### Walker Delta

Inputs:

* altitude or semi-major axis;
* inclination;
* total satellites (T);
* planes (P);
* phasing (F);
* initial RAAN offset;
* initial phase offset.

Constraints:

* (T) divisible by (P);
* equal RAAN spacing;
* equal satellite count per plane;
* uniform along-track spacing.

### Explicit asymmetric multi-plane

Inputs shall be a list of planes. Each plane shall specify:

* RAAN;
* zero or more orbital-element overrides;
* arbitrary list of satellite phase positions.

This generator shall support:

* nonuniform plane spacing;
* unequal satellites per plane;
* nonuniform along-track spacing;
* empty or partially occupied planes;
* common or plane-specific altitude and inclination.

### Repeating/common-ground-track

Inputs:

* repeat cycle in sidereal days;
* number of orbital revolutions during the repeat cycle;
* inclination and eccentricity;
* selected phase-slot identifiers;
* RAAN/mean-anomaly phase law;
* optional J2-corrected orbit solver.

The generator shall first determine a resonant orbit, then generate the allowed RAAN and mean-anomaly slot pairs and select either all or a subset of those slots.

### Flower/lattice constellation

Inputs:

* repeat integers;
* lattice/phasing parameters;
* number of candidate slots;
* selected occupied slots;
* common orbital-element template.

The initial implementation may accept explicit ((\Omega,M_0)) pairs generated by an external Flower-constellation solver. The simulator shall not require all lattice slots to be occupied.

### Multi-shell constellation

Inputs shall be a list of independently generated subconstellations. Each shell may use a different:

* altitude;
* inclination;
* plane configuration;
* generator type;
* satellite count;
* epoch or phase offset.

The resulting satellite lists shall be combined before propagation and coverage evaluation.

## 3. Service-region model

The simulator shall accept:

* polygon or multipolygon service regions;
* optional exclusion regions;
* ground-point grid resolution;
* boundary sampling resolution;
* point weights or traffic weights;
* optional fixed critical locations.

The design shall be evaluated at interior grid points, polygon boundaries and identified worst-case refinement points.

## 4. Usable-link definition

Geometric visibility alone shall not define coverage.

A satellite shall be considered usable only when all configured conditions are satisfied, including as applicable:

* elevation above acquisition or serving threshold;
* maximum slant range;
* minimum link margin;
* satellite beam steering limit;
* beam availability;
* capacity or admission constraint;
* feeder-link or ISL availability;
* Doppler or range-rate acquisition limit.

The evaluator shall return continuous usable-link intervals for every ground point and satellite.

## 5. Continuity and handover requirements

The following shall be separate parameters:

* normal coverage multiplicity (k);
* minimum make-before-break overlap duration;
* maximum permitted uncovered gap;
* minimum target dwell time after handover;
* minimum target elevation or link margin during acquisition;
* whether source and target must be in different planes;
* whether source and target must be different satellites only;
* optional maximum handover rate.

### Continuous (k=2)

Require at least two usable satellites at every point and time.

### Continuous (k=1) with make-before-break

Require continuous service by at least one satellite.

For every transition between serving satellites, require source and target usable intervals to overlap for at least:

[
\tau_{\mathrm{overlap}}\geq\tau_{\mathrm{HO}}.
]

The target shall remain usable for at least the configured minimum dwell time after the handover.

### Buffered break-before-make

When explicitly enabled, allow the next target interval to begin after the source interval ends, provided:

[
0 < t_{\mathrm{target,start}}-t_{\mathrm{source,end}}
\leq \tau_{\mathrm{gap,max}}.
]

This is not continuous (k=1). It is interrupted coverage with a bounded permitted gap.

The simulator shall report make-before-break transitions and buffered-gap transitions separately.

## 6. Event-based coverage analysis

Coverage transitions shall be calculated as events rather than solely by fixed time stepping.

The implementation shall:

1. Coarsely propagate to bracket visibility or link-margin transitions.
2. Solve each transition time using root finding.
3. Produce continuous usable intervals.
4. Sweep interval endpoints to calculate coverage multiplicity.
5. Merge intervals to calculate uncovered gaps.
6. Build a handover-feasibility graph.
7. Determine whether a valid serving path spans the simulation interval.

The transition-time numerical tolerance should be materially smaller than the permitted gap. A millisecond-scale permitted gap therefore requires event solving to sub-millisecond or comparable accuracy; a one-second or even 100-millisecond propagation grid is insufficient.

## 7. Handover-feasibility graph

For each ground point:

* each node represents one satellite usable interval;
* a make-before-break edge exists when two intervals overlap by at least the configured handover duration;
* a buffered-gap edge exists when the positive interval gap is no greater than the permitted maximum;
* an edge is rejected if the target does not provide sufficient remaining dwell time;
* a design is feasible when a path exists from the beginning to the end of the evaluation interval.

This graph-based test is preferable to checking only average or instantaneous visibility counts.

## 8. Outputs

For each candidate constellation, report:

* total satellites;
* number of distinct orbital planes;
* satellites per plane;
* minimum instantaneous multiplicity;
* percentage of region and time satisfying each (k);
* worst uncovered gap;
* worst valid handover overlap;
* number of failed handover transitions;
* maximum and average handover rate;
* minimum target dwell time;
* worst elevation, slant range and link margin;
* worst geographic point and time;
* result separately for geometric visibility and usable-link coverage.

## 9. Search and optimisation interface

The builder shall support:

* exhaustive Walker (T/P/F) enumeration;
* enumeration of all divisors (P\mid T);
* all valid (F) values;
* altitude and inclination sweeps;
* arbitrary RAAN and phase optimisation;
* plane occupancy optimisation;
* lattice-slot selection;
* multi-shell combinations;
* lexicographic or weighted objectives.

A recommended lexicographic objective is:

1. satisfy all service and handover constraints;
2. minimise total satellites;
3. minimise number of planes;
4. maximise worst-case overlap and link margin;
5. minimise handover rate and operational complexity.

# **A classical Walker Delta cannot represent most of these designs.** Its (T/P/F) notation assumes:

* common (a,e,i,\omega);
* (P) equally spaced planes;
* the same number (S=T/P) of satellites per plane;
* uniform along-track spacing;
* one global inter-plane phasing factor (F).

The adjacent-plane phase offset is (360F/T). ([MathWorks][1])

A “generalized Walker” can represent the advanced designs only by relaxing those assumptions and allowing arbitrary per-plane RAANs and arbitrary per-satellite phase positions. At that point it is better described as a **general orbital-element constellation model**, with Walker Delta implemented as one generator.

## Which designs require uneven planes?

| Constellation type                 |                               Uneven RAAN spacing |        Unequal satellites per plane |    Different orbital elements |
| ---------------------------------- | ------------------------------------------------: | ----------------------------------: | ----------------------------: |
| Walker Delta                       |                                                No |                                  No |                            No |
| Asymmetric multi-plane             |                                           Usually |                            Optional |                      Optional |
| Unequal-occupancy Walker-like      |                                    No or optional |                                 Yes |                            No |
| Common/repeating-ground-track      |                                   Not necessarily | Often represented as selected slots | Usually common (a,e,i,\omega) |
| Flower/lattice constellation       | RAAN–phase pairs follow a lattice, not Walker (F) |         Can be restricted/subsetted | Usually common (a,e,i,\omega) |
| Complementary multi-shell          |                                         Per-shell |                           Per-shell |           Yes, between shells |
| Completely optimized constellation |                                         Arbitrary |                           Arbitrary |                     Arbitrary |

Flower constellations commonly share (a,e,i,\omega), with RAAN and initial mean anomaly providing the constellation phasing. They are therefore not necessarily “uneven planes” in an arbitrary sense, but they generally do not reduce to equal Walker planes with one (F). ([ui.adsabs.harvard.edu][2])

# Reference Python structure

This is not a propagator; it shows the required builder abstraction.

```python
from __future__ import annotations

from dataclasses import dataclass
from math import tau
from typing import Iterable, Sequence


def wrap_angle(x: float) -> float:
    return x % tau


@dataclass(frozen=True)
class OrbitElements:
    """Osculating or mean Keplerian elements at a common epoch."""

    a_km: float
    eccentricity: float
    inclination_rad: float
    raan_rad: float
    arg_perigee_rad: float
    mean_anomaly_rad: float
    epoch_s: float = 0.0


@dataclass(frozen=True)
class Satellite:
    satellite_id: str
    orbit: OrbitElements
    shell_id: str = "shell-0"
    plane_id: str | None = None
    slot_id: str | None = None


@dataclass(frozen=True)
class OrbitTemplate:
    a_km: float
    eccentricity: float
    inclination_rad: float
    arg_perigee_rad: float = 0.0
    epoch_s: float = 0.0


@dataclass(frozen=True)
class PlaneSpec:
    raan_rad: float
    phase_rad: Sequence[float]

    # Optional plane-specific overrides.
    a_km: float | None = None
    eccentricity: float | None = None
    inclination_rad: float | None = None
    arg_perigee_rad: float | None = None


def walker_delta(
    template: OrbitTemplate,
    total_satellites: int,
    plane_count: int,
    phasing: int,
    *,
    raan_offset_rad: float = 0.0,
    phase_offset_rad: float = 0.0,
    shell_id: str = "walker",
) -> list[Satellite]:
    """
    Generate a classical Walker Delta constellation.

    Omega_p = Omega_0 + 2*pi*p/P
    M_p,s   = M_0 + 2*pi*s/S + 2*pi*F*p/T
    """

    if total_satellites <= 0 or plane_count <= 0:
        raise ValueError("Satellite and plane counts must be positive")

    if total_satellites % plane_count != 0:
        raise ValueError("T must be divisible by P")

    if not 0 <= phasing < plane_count:
        raise ValueError("F must satisfy 0 <= F < P")

    satellites_per_plane = total_satellites // plane_count
    satellites: list[Satellite] = []

    for p in range(plane_count):
        raan = wrap_angle(raan_offset_rad + tau * p / plane_count)

        for s in range(satellites_per_plane):
            mean_anomaly = wrap_angle(
                phase_offset_rad
                + tau * s / satellites_per_plane
                + tau * phasing * p / total_satellites
            )

            orbit = OrbitElements(
                a_km=template.a_km,
                eccentricity=template.eccentricity,
                inclination_rad=template.inclination_rad,
                raan_rad=raan,
                arg_perigee_rad=template.arg_perigee_rad,
                mean_anomaly_rad=mean_anomaly,
                epoch_s=template.epoch_s,
            )

            satellites.append(
                Satellite(
                    satellite_id=f"{shell_id}-P{p:02d}-S{s:02d}",
                    orbit=orbit,
                    shell_id=shell_id,
                    plane_id=f"P{p:02d}",
                    slot_id=f"S{s:02d}",
                )
            )

    return satellites
```

The Walker phase equation above matches the standard adjacent-plane shift (F,360^\circ/T). ([MathWorks][1])

### Arbitrary asymmetric planes

```python
def explicit_planes(
    template: OrbitTemplate,
    planes: Sequence[PlaneSpec],
    *,
    shell_id: str = "asymmetric",
) -> list[Satellite]:
    """
    Generate arbitrary plane spacing, population and satellite phasing.

    This is the main generalized constellation builder.
    """

    satellites: list[Satellite] = []

    for p, plane in enumerate(planes):
        a_km = plane.a_km if plane.a_km is not None else template.a_km
        eccentricity = (
            plane.eccentricity
            if plane.eccentricity is not None
            else template.eccentricity
        )
        inclination = (
            plane.inclination_rad
            if plane.inclination_rad is not None
            else template.inclination_rad
        )
        arg_perigee = (
            plane.arg_perigee_rad
            if plane.arg_perigee_rad is not None
            else template.arg_perigee_rad
        )

        for s, phase in enumerate(plane.phase_rad):
            orbit = OrbitElements(
                a_km=a_km,
                eccentricity=eccentricity,
                inclination_rad=inclination,
                raan_rad=wrap_angle(plane.raan_rad),
                arg_perigee_rad=wrap_angle(arg_perigee),
                mean_anomaly_rad=wrap_angle(phase),
                epoch_s=template.epoch_s,
            )

            satellites.append(
                Satellite(
                    satellite_id=f"{shell_id}-P{p:02d}-S{s:02d}",
                    orbit=orbit,
                    shell_id=shell_id,
                    plane_id=f"P{p:02d}",
                    slot_id=f"S{s:02d}",
                )
            )

    return satellites
```

### Generic lattice/common-track slots

For an idealized Flower/common-track constellation, all satellites can share (a,e,i,\omega), while each slot supplies an allowed ((\Omega,M_0)) pair.

```python
@dataclass(frozen=True)
class PhaseSlot:
    slot_id: str
    raan_rad: float
    mean_anomaly_rad: float


def phase_slot_constellation(
    template: OrbitTemplate,
    slots: Iterable[PhaseSlot],
    *,
    shell_id: str = "lattice",
) -> list[Satellite]:
    satellites: list[Satellite] = []

    for index, slot in enumerate(slots):
        orbit = OrbitElements(
            a_km=template.a_km,
            eccentricity=template.eccentricity,
            inclination_rad=template.inclination_rad,
            raan_rad=wrap_angle(slot.raan_rad),
            arg_perigee_rad=template.arg_perigee_rad,
            mean_anomaly_rad=wrap_angle(slot.mean_anomaly_rad),
            epoch_s=template.epoch_s,
        )

        satellites.append(
            Satellite(
                satellite_id=f"{shell_id}-{index:03d}",
                orbit=orbit,
                shell_id=shell_id,
                slot_id=slot.slot_id,
            )
        )

    return satellites
```

For an ideal two-body Flower relation, the repeat condition and one common-track phase relation can be expressed as:

[
N_pT_p=N_dT_d,
\qquad
N_p\Omega_j\equiv-N_dM_j\pmod{2\pi}.
]

([Zaguan][3])

A simple seed-slot generator is therefore:

```python
def ideal_common_track_slots(
    *,
    petal_count: int,
    repeat_days: int,
    raan_values_rad: Sequence[float],
    phase_constant_rad: float = 0.0,
) -> list[PhaseSlot]:
    """
    Idealized two-body phase relation.

    Production code must replace or refine this with a J2-aware resonant
    orbit and phasing solver.
    """

    if petal_count <= 0 or repeat_days <= 0:
        raise ValueError("Repeat integers must be positive")

    slots: list[PhaseSlot] = []

    for index, raan in enumerate(raan_values_rad):
        mean_anomaly = wrap_angle(
            phase_constant_rad
            - (petal_count / repeat_days) * raan
        )

        slots.append(
            PhaseSlot(
                slot_id=f"L{index:03d}",
                raan_rad=wrap_angle(raan),
                mean_anomaly_rad=mean_anomaly,
            )
        )

    return slots
```

In production, repeat-ground-track altitude must be solved using the chosen force model because Earth rotation and secular nodal motion, particularly J2, alter the repeat condition. ([arc.aiaa.org][4])

## Continuity and handover evaluator

The critical abstraction is a list of usable intervals:

```python
@dataclass(frozen=True)
class UsableInterval:
    satellite_id: str
    start_s: float
    end_s: float

    def __post_init__(self) -> None:
        if self.end_s < self.start_s:
            raise ValueError("Interval end precedes start")


@dataclass(frozen=True)
class ContinuityRequirement:
    normal_k: int = 1
    min_handover_overlap_s: float = 0.0
    max_buffered_gap_s: float = 0.0
    min_target_dwell_s: float = 0.0
    permit_buffered_break_before_make: bool = False
```

Build a directed handover graph:

```python
def transition_type(
    source: UsableInterval,
    target: UsableInterval,
    requirement: ContinuityRequirement,
) -> str | None:
    if source.satellite_id == target.satellite_id:
        return None

    if target.end_s <= source.end_s:
        # Target does not extend service beyond the source.
        return None

    overlap = min(source.end_s, target.end_s) - max(
        source.start_s, target.start_s
    )

    if (
        overlap >= requirement.min_handover_overlap_s
        and target.end_s - source.end_s
        >= requirement.min_target_dwell_s
    ):
        return "make-before-break"

    gap = target.start_s - source.end_s

    if (
        requirement.permit_buffered_break_before_make
        and 0.0 < gap <= requirement.max_buffered_gap_s
        and target.end_s - target.start_s
        >= requirement.min_target_dwell_s
    ):
        return "buffered-break-before-make"

    return None
```

Determine whether a service chain covers the complete evaluation interval:

```python
from collections import deque


def find_service_path(
    intervals: Sequence[UsableInterval],
    start_s: float,
    end_s: float,
    requirement: ContinuityRequirement,
) -> list[UsableInterval] | None:
    clipped = [
        interval
        for interval in intervals
        if interval.end_s >= start_s and interval.start_s <= end_s
    ]
    clipped.sort(key=lambda x: (x.start_s, -x.end_s))

    start_nodes = [
        index
        for index, interval in enumerate(clipped)
        if interval.start_s <= start_s <= interval.end_s
    ]

    queue: deque[int] = deque(start_nodes)
    predecessor: dict[int, int | None] = {
        index: None for index in start_nodes
    }

    goal: int | None = None

    while queue:
        current_index = queue.popleft()
        current = clipped[current_index]

        if current.end_s >= end_s:
            goal = current_index
            break

        for next_index, candidate in enumerate(clipped):
            if next_index in predecessor:
                continue

            if transition_type(current, candidate, requirement) is not None:
                predecessor[next_index] = current_index
                queue.append(next_index)

    if goal is None:
        return None

    path: list[UsableInterval] = []
    node: int | None = goal

    while node is not None:
        path.append(clipped[node])
        node = predecessor[node]

    path.reverse()
    return path
```

For large constellations, replace the (O(n^2)) edge search with an interval tree or sweep-line structure.

## Recommended top-level simulation flow

```text
for each candidate constellation:
    satellites = selected_generator(candidate_parameters)

    for each service-region sample point:
        for each satellite:
            propagate orbit
            bracket usable-link entry and exit events
            refine event times with root finding
            store usable intervals

        calculate multiplicity timeline
        calculate uncovered gaps
        build handover graph
        search for a valid end-to-end serving path

    refine around worst geographic points and transition times
    aggregate worst-case results
    reject or rank candidate
```

One practical warning: a **millisecond-scale geometric coverage gap** is far smaller than normal coarse constellation-analysis resolution. At LEO velocity, 10 ms corresponds to only roughly tens of metres of satellite travel. Orbit, attitude, beam-edge and propagation uncertainties can dominate such a narrow margin. The software can support it, but it should report numerical and modelling margin separately rather than treating a nominal 5–10 ms result as robust.
